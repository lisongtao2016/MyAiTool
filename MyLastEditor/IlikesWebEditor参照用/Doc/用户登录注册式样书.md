# 用户登录注册式样书 - 数据库互动篇

## 概述
本文档定义 IlikesWebEditor 用户认证系统（登录、注册）与数据库的交互规范，包括数据模型、API接口、验证规则和安全考虑。

## 数据库设计

### 1. 用户表结构 (Users)
```sql
CREATE TABLE Users (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    Username NVARCHAR(100) NOT NULL UNIQUE,
    Email NVARCHAR(255) NOT NULL UNIQUE,
    PasswordHash NVARCHAR(255) NOT NULL,
    DisplayName NVARCHAR(100),
    CreatedDate DATETIME DEFAULT CURRENT_TIMESTAMP,
    LastLoginDate DATETIME,
    IsActive BOOLEAN DEFAULT 1,
    Role NVARCHAR(50) DEFAULT 'user'
);
```

### 2. 字段说明
- **Id**：主键，自增整数
- **Username**：用户名，唯一，3-50字符
- **Email**：邮箱地址，唯一，标准邮箱格式
- **PasswordHash**：密码哈希值，使用BCrypt或类似算法
- **DisplayName**：显示名称，可选，1-100字符
- **CreatedDate**：创建时间，自动记录
- **LastLoginDate**：最后登录时间
- **IsActive**：账户状态，1=激活，0=禁用
- **Role**：用户角色，默认'user'，可选'admin'

## API接口规范

### 1. 用户注册接口
**端点**：`WebServ.asmx/RegisterUser`

**请求参数**：
```json
{
    "username": "string (必填)",
    "email": "string (必填)", 
    "password": "string (必填)",
    "displayName": "string (可选)"
}
```

**响应格式**：
```json
{
    "success": "boolean",
    "message": "string",
    "userId": "number (成功时)",
    "displayName": "string (成功时)"
}
```

**业务逻辑**：
1. 验证输入数据格式
2. 检查用户名和邮箱是否已存在
3. 对密码进行哈希处理
4. 创建用户记录
5. 返回创建结果

### 2. 用户登录接口
**端点**：`WebServ.asmx/LoginUser`

**请求参数**：
```json
{
    "identifier": "string (用户名或邮箱)",
    "password": "string"
}
```

**响应格式**：
```json
{
    "success": "boolean",
    "message": "string",
    "userId": "number (成功时)",
    "username": "string (成功时)",
    "displayName": "string (成功时)",
    "email": "string (成功时)",
    "role": "string (成功时)"
}
```

**业务逻辑**：
1. 根据identifier查找用户（用户名或邮箱）
2. 验证密码哈希
3. 检查账户状态（IsActive）
4. 更新LastLoginDate
5. 返回用户信息和登录令牌

### 3. 会话检查接口
**端点**：`WebServ.asmx/CheckSession`

**请求参数**：无

**响应格式**：
```json
{
    "success": "boolean",
    "message": "string"
}
```

**用途**：验证用户会话是否有效

## 数据验证规则

### 1. 用户名验证
- **长度**：3-50个字符
- **格式**：字母、数字、下划线、连字符
- **唯一性**：数据库级别唯一约束
- **保留字**：避免使用admin、system等保留字

### 2. 邮箱验证
- **格式**：标准邮箱格式（正则表达式验证）
- **唯一性**：数据库级别唯一约束
- **域名验证**：可选的域名白名单

### 3. 密码验证
- **长度**：至少8个字符
- **复杂度**：必须包含字母和数字
- **哈希算法**：使用BCrypt或Argon2
- **盐值**：每个密码使用唯一盐值

### 4. 显示名称验证
- **长度**：1-100个字符
- **可选性**：可为空，默认使用用户名
- **字符限制**：允许大多数Unicode字符

## 安全规范

### 1. 密码安全
- 绝不存储明文密码
- 使用强哈希算法（BCrypt/Argon2）
- 每个密码使用唯一盐值
- 密码传输使用HTTPS加密

### 2. 会话管理
- 使用安全的会话令牌
- 设置合理的会话超时（如30分钟）
- 支持会话注销
- 防止会话固定攻击

### 3. 输入验证
- 服务器端验证所有输入
- 防止SQL注入（使用参数化查询）
- 防止XSS攻击（输出编码）
- 限制请求频率

### 4. 错误处理
- 不泄露敏感信息（如用户是否存在）
- 统一的错误响应格式
- 详细的错误日志（服务器端）
- 用户友好的错误消息

## 业务逻辑流程

### 1. 注册流程
```
前端 → 后端 → 数据库
1. 用户提交注册表单
2. 前端验证基本格式
3. 发送注册请求到API
4. 后端验证数据完整性
5. 检查用户名/邮箱唯一性
6. 密码哈希处理
7. 创建用户记录
8. 返回注册结果
9. 前端显示成功/错误消息
```

### 2. 登录流程
```
前端 → 后端 → 数据库
1. 用户提交登录表单
2. 前端验证输入非空
3. 发送登录请求到API
4. 后端根据identifier查找用户
5. 验证密码哈希
6. 检查账户状态
7. 更新最后登录时间
8. 生成会话令牌
9. 返回登录结果和用户信息
10. 前端保存登录状态
```

### 3. 会话验证流程
```
前端 → 后端 → 数据库
1. 应用启动时检查会话
2. 发送会话检查请求
3. 后端验证会话令牌
4. 检查会话有效期
5. 返回会话状态
6. 前端根据状态跳转
```
