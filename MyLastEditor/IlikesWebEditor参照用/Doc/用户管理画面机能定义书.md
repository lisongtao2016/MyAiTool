# 用户管理画面机能定义书

## 📋 画面概要

**画面名称**: 用户信息管理画面  
**文件名**: `user_management.html`（待创建）  
**用途**: 管理员对用户账户进行查看、编辑、禁用/启用等维护操作

---

## 🎯 核心机能

### 1. 用户列表查询

#### 1.1 查询条件
| 字段 | 类型 | 说明 |
|------|------|------|
| 关键词 | 文本 | 搜索用户名/邮箱/显示名称 |
| 角色 | 下拉框 | 全部/user/admin |
| 状态 | 下拉框 | 全部/激活/禁用 |
| 注册时间 | 日期范围 | 起始日期 - 结束日期 |

#### 1.2 列表显示字段
| 字段 | 说明 | 排序 |
|------|------|------|
| ID | 用户ID | ✅ |
| 用户名 | Username | ✅ |
| 邮箱 | Email | ✅ |
| 显示名称 | DisplayName | - |
| 角色 | Role | ✅ |
| 状态 | IsActive | ✅ |
| 注册时间 | CreatedDate | ✅ |
| 最后登录 | LastLoginDate | ✅ |
| 操作 | 编辑/禁用/删除 | - |

#### 1.3 处理逻辑
```
1. 调用 WebServ.asmx/GetUserList
2. 参数：keyword, role, status, startDate, endDate, page, pageSize
3. SQL 查询：
   SELECT * FROM Users 
   WHERE (Username LIKE @keyword OR Email LIKE @keyword OR DisplayName LIKE @keyword)
     AND (@role = '' OR Role = @role)
     AND (@status = -1 OR IsActive = @status)
     AND (@startDate IS NULL OR CreatedDate >= @startDate)
     AND (@endDate IS NULL OR CreatedDate <= @endDate)
   ORDER BY CreatedDate DESC
   LIMIT @pageSize OFFSET @offset
4. 返回分页数据 + 总记录数
```

### 2. 用户详情查看

#### 2.1 触发方式
- 点击列表中的"编辑"按钮
- 或双击用户行

#### 2.2 显示信息
```
基本信息:
  - 用户ID（只读）
  - 用户名（只读）
  - 邮箱（只读）
  - 显示名称（可编辑）
  - 角色（可编辑：user/admin）
  - 状态（可切换：激活/禁用）

时间信息:
  - 注册时间（只读）
  - 最后登录时间（只读）
  - 最后修改时间（只读）
```

---

### 3. 用户信息编辑

#### 3.1 可编辑字段
| 字段 | 类型 | 验证规则 |
|------|------|----------|
| 显示名称 | 文本 | 最多100字符 |
| 角色 | 下拉框 | user / admin |
| 状态 | 单选框 | 激活 / 禁用 |

#### 3.2 处理逻辑
```
1. 前端验证输入
2. 调用 WebServ.asmx/UpdateUser
3. 参数：id, displayName, role, isActive
4. 后端更新：
   UPDATE Users 
   SET DisplayName = @displayName,
       Role = @role,
       IsActive = @isActive,
       ModifiedDate = CURRENT_TIMESTAMP
   WHERE Id = @id
5. 成功：刷新列表 + 显示成功提示
6. 失败：显示错误信息
```

#### 3.3 权限控制
- **admin 角色**: 可编辑所有字段
- **user 角色**: 仅可查看，不可编辑他人信息

### 4. 用户状态管理

#### 4.1 禁用用户
```
触发: 点击"禁用"按钮
确认: "确定要禁用用户 [用户名] 吗？"
处理:
  - 设置 IsActive = 0
  - 记录操作日志
  - 用户下次登录时拒绝
结果: 列表中状态变为"禁用"
```

#### 4.2 启用用户
```
触发: 点击"启用"按钮
处理:
  - 设置 IsActive = 1
  - 记录操作日志
  - 用户可正常登录
结果: 列表中状态变为"激活"
```

---

### 5. 用户删除（软删除）

#### 5.1 删除逻辑
```
触发: 点击"删除"按钮
确认: "确定要删除用户 [用户名] 吗？此操作不可恢复！"
处理:
  - 方案A（推荐）: 设置 IsActive = 0（软删除）
  - 方案B: 物理删除（需检查关联数据）
    - 检查 EditorContents.Author 是否有引用
    - 检查 Projects.CreatedBy 是否有引用
    - 有引用则禁止删除
结果: 从列表中移除
```

#### 5.2 级联处理
- **EditorContents**: 保留内容，Author 字段标记为"已删除用户"
- **Projects**: 转移给其他用户或标记为"无主项目"

---

### 6. 密码重置

#### 6.1 功能说明
- 管理员可为忘记密码的用户重置密码
- 生成临时密码并显示给管理员
- 用户首次登录时必须修改密码

#### 6.2 处理流程
```
1. 点击"重置密码"按钮
2. 确认: "确定要重置用户 [用户名] 的密码吗？"
3. 生成随机密码（8位字母数字组合）
4. SHA256 加密后更新 PasswordHash
5. 显示临时密码给管理员（仅显示一次）
6. 标记用户需要修改密码（新增字段 NeedChangePassword）
7. 用户下次登录时强制跳转至修改密码页面
```

## 📡 API 接口

### GetUserList
```javascript
POST WebServ.asmx/GetUserList
{
  keyword: "搜索关键词",
  role: "user/admin/''",
  status: "-1/0/1",
  startDate: "2026-01-01",
  endDate: "2026-12-31",
  page: 1,
  pageSize: 20
}
响应: {
  success: true,
  users: [...],
  total: 100,
  page: 1,
  pageSize: 20
}
```

### UpdateUser
```javascript
POST WebServ.asmx/UpdateUser
{
  id: 1,
  displayName: "新名称",
  role: "admin",
  isActive: true
}
响应: { success: true/false, message: "..." }
```

### ResetPassword
```javascript
POST WebServ.asmx/ResetPassword
{
  userId: 1
}
响应: { success: true, tempPassword: "Abc12345" }
```

### DeleteUser
```javascript
POST WebServ.asmx/DeleteUser
{
  userId: 1,
  forceDelete: false  // true=物理删除, false=软删除
}
响应: { success: true/false, message: "..." }
```

## 🔄 业务流程图

```
管理员访问 user_management.html
    ↓
验证角色 = admin
    ↓ 失败
拒绝访问，跳转主页
    ↓ 成功
加载用户列表（默认显示前20条）
    ↓
用户操作：
  ├─ 查询 → 输入条件 → 调用 GetUserList → 刷新表格
  ├─ 编辑 → 点击编辑 → 弹出对话框 → 修改 → 调用 UpdateUser → 刷新
  ├─ 禁用 → 点击禁用 → 确认 → 调用 UpdateUser(isActive=false) → 刷新
  ├─ 删除 → 点击删除 → 二次确认 → 调用 DeleteUser → 刷新
  └─ 重置密码 → 点击重置 → 确认 → 调用 ResetPassword → 显示临时密码
```

## ⚠️ 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 无权限访问 | 显示"无权访问" + 跳转主页 |
| 删除有引用的用户 | 提示"该用户有关联数据，请先处理" |
| 网络超时 | 显示"请求超时，请重试" |
| 并发冲突 | 乐观锁检测，提示"数据已被他人修改" |
| 数据库错误 | 记录日志 + 显示友好提示 |
