# 前端无法加载任务数据 - 故障排除指南

## 问题描述
打开 `richengbiao.html` 时显示："无法加载任务数据，请确保后端服务器正在运行"

## 根本原因分析

### 已修复的问题 ✅

1. **端口不一致** 
   - ❌ 之前：前端配置 3001，后端配置 5288
   - ✅ 现在：统一为 3001

2. **数据库路径错误**
   - ❌ 之前：查找 `../../schedule.db`
   - ✅ 现在：查找 `../../data/schedule.db`（带备用路径）

## 快速解决步骤

### 方法 1：使用诊断脚本（推荐）⭐

```powershell
# 在项目根目录执行
.\start_with_diagnostics.ps1
```

该脚本会自动：
- ✅ 检查 .NET SDK
- ✅ 验证数据库文件
- ✅ 检查端口占用
- ✅ 启动服务器
- ✅ 测试 API 连接
- ✅ 自动打开浏览器

### 方法 2：手动启动

#### 步骤 1: 初始化数据库（首次运行）

```bash
# 确保 data/schedule.db 存在
sqlite3 data/schedule.db ".read data/schema.sql"
```

#### 步骤 2: 启动后端服务器

```bash
cd ScheduleApi
dotnet run
```

**成功标志**：
```

Database exists: True
现在正在监听: http://localhost:3001
应用已启动。按 Ctrl+C 关闭。
```

#### 步骤 3: 打开前端

```bash

start src/frontend/richengbiao.html

# 方式 B: 直接双击文件
# 或访问测试页面
start src/frontend/test_schedule_api.html
```

## 常见问题排查

### 问题 1: dotnet run 失败

#### 错误：NU1301 - 无法连接到 nuget.org

**解决方案**：
```bash
# 清除 NuGet 缓存
dotnet nuget locals all --clear

# 重试
dotnet restore
dotnet run
```

#### 错误：端口 3001 被占用

**解决方案**：
```powershell
# 查找占用端口的进程
netstat -ano | findstr :3001

# 终止进程（替换 <PID> 为实际进程ID）
taskkill /PID <PID> /F

# 或使用诊断脚本自动处理
.\start_with_diagnostics.ps1
```

### 问题 2: 数据库文件不存在

**症状**：控制台显示 `Database exists: False`

**解决方案**：
```bash
# 重新初始化数据库
sqlite3 data/schedule.db ".read data/schema.sql"

# 验证
sqlite3 data/schedule.db "SELECT COUNT(*) FROM tasks;"
```

### 问题 3: CORS 错误

**症状**：浏览器控制台显示 CORS 策略阻止请求

**解决方案**：
后端已配置 CORS，确认 `Program.cs` 中有：
```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowAll", policy =>
    {
        policy.AllowAnyOrigin()
              .AllowAnyMethod()
              .AllowAnyHeader();
    });
});

app.UseCors("AllowAll");
```

### 问题 4: 前端 API 地址错误

**检查**：打开 `richengbiao.html`，搜索 `API_BASE_URL`

**应该是**：
```javascript
const API_BASE_URL = 'http://localhost:3001/api';
```

如果不是，修改为上述值并保存。

### 问题 5: 浏览器控制台错误

**调试步骤**：
1. 按 F12 打开开发者工具
2. 切换到 Console 标签
3. 刷新页面
4. 查看错误信息

**常见错误及解决**：

| 错误信息 | 原因 | 解决方案 |
|---------|------|---------|
| Failed to fetch | 后端未启动 | 启动 `dotnet run` |
| net::ERR_CONNECTION_REFUSED | 端口错误 | 检查端口是否为 3001 |
| CORS policy | CORS 配置 | 检查后端 CORS 设置 |
| 404 Not Found | API 路径错误 | 检查 API_BASE_URL |

## 验证清单

在报告问题前，请确认：

- [ ] .NET SDK 已安装（`dotnet --version`）
- [ ] 数据库文件存在（`data/schedule.db`）
- [ ] 后端服务器正在运行（控制台显示监听 3001）
- [ ] 浏览器可以访问 `http://localhost:3001/health`
- [ ] 前端 `API_BASE_URL` 配置为 `http://localhost:3001/api`
- [ ] 浏览器控制台无 CORS 错误
- [ ] 防火墙未阻止端口 3001

如果以上方法都无效，执行完整重置：

```powershell

Get-Process dotnet | Stop-Process -Force

# 2. 删除数据库（备份重要数据）

# 3. 重新初始化
sqlite3 data/schedule.db ".read data/schema.sql"

# 4. 清理并重建
cd ScheduleApi
dotnet clean
dotnet build

# 5. 使用诊断脚本启动
cd ..
.\start_with_diagnostics.ps1
```
