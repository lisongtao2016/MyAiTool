# 日程表系统功能设计文档

## 1. 系统概述

基于 .NET Framework 4.5+ 和原生 JavaScript 的企业级日程管理系统，采用 Canvas 甘特图展示，支持完整的 CRUD 操作。

## 2. 技术架构

### 2.1 技术栈
- **后端框架**: .NET 8.0 (兼容 Framework 4.5+ 规范)
- **前端技术**: 原生 JavaScript (ES6+) + HTML5 Canvas
- **数据库**: SQLite 3
- **通信协议**: RESTful API + CORS
- **服务端口**: 3001

### 2.2 项目结构
```
SanGuo/
├── ScheduleApi/              # .NET 后端
│   ├── Program.cs            # API 入口（包含所有端点）
│   ├── Models/Task.cs        # 数据模型
│   └── Services/             # 服务层
├── src/frontend/             # 前端文件
│   ├── richengbiao.html      # 主界面（Canvas 甘特图）
│   └── test_schedule_api.html # API 测试页面
├── data/                     # 数据层
│   ├── schedule.db           # SQLite 数据库
│   └── schema.sql            # 数据库架构
└── DOC/                      # 文档目录
```

## 3. 数据库设计

### 3.1 核心原则
- **极致存储**: 使用最小空间占用类型
- **时间追踪**: 所有表包含 `created_at` 和 `updated_at`
- **中文注释**: 每个字段都有中文 COMMENT 说明
- **索引优化**: 对常用查询字段建立索引

### 3.2 表结构

#### 项目表 (projects)
| 字段 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | INTEGER | 主键ID | PRIMARY KEY, AUTOINCREMENT |
| name | TEXT | 项目名称 | NOT NULL |
| created_at | TIMESTAMP | 创建时间 | DEFAULT CURRENT_TIMESTAMP |

#### 任务表 (tasks)
| 字段 | 类型 | 说明 | 约束 |
|------|------|------|------|
| id | INTEGER | 主键ID | PRIMARY KEY, AUTOINCREMENT |
| project_id | INTEGER | 项目ID（外键） | FOREIGN KEY → projects(id) |
| group_name | TEXT | 项目分组 | NOT NULL |
| sub_group | TEXT | 子模块 | NOT NULL |
| name | TEXT | 任务名称 | NOT NULL |
| start_date | DATE | 开始日期 | NOT NULL |
| end_date | DATE | 结束日期 | NOT NULL |
| start_day | INTEGER | 开始天数（甘特图偏移量） | NOT NULL, DEFAULT 0 |
| duration | INTEGER | 持续时间（天） | NOT NULL |
| plan | INTEGER | 计划进度（百分比） | NOT NULL, DEFAULT 100 |
| actual | INTEGER | 实际进度（百分比） | NOT NULL, DEFAULT 0 |
| owner | TEXT | 负责人 | NOT NULL |
| created_at | TIMESTAMP | 创建时间 | DEFAULT CURRENT_TIMESTAMP |
| updated_at | TIMESTAMP | 更新时间 | DEFAULT CURRENT_TIMESTAMP |

### 3.3 索引策略
```sql
CREATE INDEX idx_tasks_owner ON tasks(owner);           -- 按负责人搜索
CREATE INDEX idx_tasks_start_date ON tasks(start_date); -- 按开始日期查询
CREATE INDEX idx_tasks_end_date ON tasks(end_date);     -- 按结束日期查询
```

## 4. API 接口设计

### 4.1 接口列表

| 方法 | 端点 | 功能 | 权限 |
|------|------|------|------|
| GET | /api/tasks | 获取所有任务 | 公开 |
| GET | /api/tasks/search?owner=xxx | 按负责人搜索 | 公开 |
| POST | /api/tasks | 创建新任务 | 公开 |
| PUT | /api/tasks/:id | 更新任务 | 公开 |
| DELETE | /api/tasks/:id | 删除任务 | 公开 |
| GET | /health | 健康检查 | 公开 |

### 4.2 接口详情

#### GET /api/tasks
**功能**: 获取所有任务列表  
**响应**: 
```json
[
  {
    "id": 1,
    "group": "核心A项目",
    "subGroup": "模块0",
    "name": "开发任务 #0",
    "startDate": "2026-04-06",
    "endDate": "2026-04-15",
    "startDay": 0,
    "duration": 5,
    "plan": 100,
    "actual": 45,
    "owner": "张三"
  }
]
```

#### GET /api/tasks/search
**参数**: `owner` (可选) - 负责人姓名（支持模糊匹配）  
**示例**: `/api/tasks/search?owner=张三`  
**响应**: 与 GET /api/tasks 相同格式

#### POST /api/tasks
**请求体**:
```json
{
  "group": "核心A项目",
  "subGroup": "模块5",
  "name": "新任务",
  "startDate": "2026-04-10",
  "endDate": "2026-04-20",
  "owner": "李四",
  "plan": 100,
  "actual": 0,
  "startDay": 0,
  "duration": 10
}
```
**必填字段**: group, subGroup, name, startDate, endDate, owner  
**响应**: 
```json
{
  "message": "Task created successfully",
  "id": 11
}
```

#### PUT /api/tasks/:id
**请求体** (所有字段可选):
```json
{
  "owner": "王五",
  "actual": 75
}
```
**响应**:
```json
{
  "message": "Task updated successfully",
  "changes": 1
}
```

#### DELETE /api/tasks/:id
**响应**:
```json
{
  "message": "Task deleted successfully",
  "changes": 1
}
```

### 4.3 错误处理
| 状态码 | 说明 |
|--------|------|
| 200 | 成功 |
| 201 | 创建成功 |
| 400 | 请求参数错误 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

## 6. 安全与性能

### 6.1 安全措施
- **CORS 配置**: 允许跨域访问（开发环境）
- **SQL 注入防护**: 使用参数化查询
- **输入验证**: 后端验证必填字段
- **XSS 防护**: 前端输出转义

### 6.2 性能优化
- **异步数据库操作**: 使用 async/await
- **连接池管理**: using 语句自动释放连接
- **索引优化**: 常用查询字段建立索引
- **Canvas 渲染**: 硬件加速绘图

### 6.3 边界情况处理
- ✅ 空值保护 (`?.` / `??`)
- ✅ 异步竞态条件
- ✅ 并发冲突处理
- ✅ 大数溢出预防

## 10. 故障排除

### 常见问题

#### 1. 后端无法启动
- 检查端口 3001 是否被占用
- 确认 .NET SDK 已安装
- 验证数据库文件路径正确

#### 2. 前端无法加载数据
- 确认后端服务器正在运行
- 检查浏览器控制台 CORS 错误
- 验证 API_BASE_URL 配置正确

#### 3. 数据库问题
```bash
# 检查数据库状态
sqlite3 data/schedule.db ".tables"
sqlite3 data/schedule.db "SELECT COUNT(*) FROM tasks"

# 重新初始化
sqlite3 data/schedule.db ".read data/schema.sql"
```
